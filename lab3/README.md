- **沿用 Lab 2 的后端 Key 方式**：Flask 在运行时从 `DEEPSEEK_API_KEY` 环境变量读取 Key。前端不输入、不接收、不保存 Key；真实 Key 不得进入 GitHub、Dockerfile、构建上下文、镜像、ACR 构建参数、日志或 Codex 对话。

**给学生的开场讲解稿（首次回复必须把这些内容真正讲出来，可调整语气，但不得只报名称或直接跳到操作）：**

> 在 Lab 2，你的聊天应用只在自己电脑上运行：本机浏览器能打开，不代表别人的设备也能访问。换一台电脑运行时，即使复制了代码，也可能因为 Python 版本、安装的依赖或启动方法不同而失败。因此 Lab 3 不再增加聊天功能，而是学习怎样把已有应用**稳定地交给另一台机器运行**，再把它放到云端让公网访问。这是两个问题，需要两类工具。
>
> **Docker 是什么？**它是一套将应用连同运行所需环境打包并以“容器”方式运行的工具和规范。对我们的 Flask 聊天程序来说，只有 `app.py` 远远不够，还需要 Python、`requirements.txt` 中的库、前端文件和正确的启动命令。**Dockerfile** 是一份文本说明书，写出选什么基础环境、复制哪些文件、安装什么依赖、运行什么命令。按 Dockerfile 构建得到的**镜像**可以理解为带版本的应用包；把镜像启动起来，才有正在处理请求的**容器**。Docker 是打包/运行机制，Dockerfile 是说明书，镜像是构建结果，容器是运行中的实例；这四者不是同一个东西。修改源码后，旧镜像和旧容器不会自己更新。
>
> 容器中还需要一个真正监听网络端口、接收浏览器请求的程序。这里用 **Gunicorn** 启动我们的 Flask 应用；Flask 负责页面和 API 的处理逻辑，Gunicorn 负责把它作为 Web 服务运行。Lab 2 的 Flask debug 服务器方便开发，但本次不拿它直接对公网服务。我们会写 Dockerfile 来说明如何准备和启动这些内容，**不要求你在自己的电脑安装 Docker**。
>
> **云计算是什么？**简单说，是按需使用云厂商提供的远程计算和网络资源。Docker 镜像解决“把应用和环境一起带走”，却不会自动把应用放到公网。阿里云 **ECS** 是一台由你管理的云服务器，类似租一台远程电脑：你要自己维护系统、安装环境并部署程序。**ECI** 是弹性容器实例：把已有镜像交给它，云平台替你启动容器，省去管理整台服务器的工作。本实验选 ECI 来集中体验容器部署。它常被归为 Serverless，但“无需管理服务器”不等于免费；实例运行期间即使无人访问也可能持续计费。
>
> 那镜像从哪里来？你的个人 **GitHub Fork** 存放源码和 Dockerfile。阿里云 **ACR（容器镜像服务）** 从指定 GitHub 分支在云端构建镜像，并保存镜像和版本，像一个镜像仓库；**ACR 不运行聊天网页**。随后 **ECI** 拉取这个镜像并运行容器，我们再配置公网入口，让浏览器通过公网 IP 访问。这样各组件的职责就不同了：GitHub 放代码，ACR 构建/存镜像，ECI 运行镜像，Gunicorn/Flask 在容器内处理网页和 API。我们选择这条路径，是为了练习“代码 → 可部署的镜像 → 云端运行”，而不必先学习维护 ECS 服务器。
>
> 最终你会亲自在浏览器打开云上的聊天页面，并能解释它为什么不依赖自己电脑一直开机。我负责本地代码、Dockerfile、Git 准备和排错；你亲自操作需要账号和费用确认的云控制台，并验证公网访问。实验 Key 只在 ECI 运行时由你设置给后端；这次短时演示使用 HTTP 且没有用户鉴权，完成 PR 后必须删除计费实例。

| 常见指令 | 在本项目里的作用 | 配置时要核对什么 |
| --- | --- | --- |
| `FROM` | 选择含 Python 的基础镜像。 | Python 版本与项目依赖兼容；基础镜像不能自带实验 Key。 |

| 自动构建 | 本实验建议先关闭，手动触发一次，避免之后文档提交意外重复构建。 |

上表中的“构建上下文”决定 `COPY` 能看到哪些文件，所以要与 Dockerfile 路径、个人目录一致。构建分支决定 ACR 从哪个已 Push 的 Git 版本取代码。海外机器构建能缓解访问海外源慢的问题，但不是保证成功的开关：失败时先读日志，尤其区分拉取依赖失败与镜像推回地域仓库失败。

> [STUDENT ACTION]

学生亲自在控制台授权个人 Fork、配置并触发构建，查看构建成功且镜像版本列表出现对应标签，然后把**非敏感**镜像地址和标签告诉 Agent。无需本机 `docker build/login/push`。这里不要求截图；Agent 尽量读取控制台可见结果，无法读取时用构建状态、地址和标签等脱敏信息，结合后续 ECI 能否拉取镜像核验。

> [REFLECTION]

先问学生：代码在哪里、构建发生在哪里、镜像保存在哪里？如果只改了本地文件但没有 Push，ACR 能构建到新代码吗？学生回答后再反馈。
