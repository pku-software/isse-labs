
# Lab 3：用 Docker 将 Lab 2 聊天应用部署到阿里云 ECI

本 Lab 延续 Lab 2：把已有的 HTML/CSS/JS + Flask + DeepSeek 聊天应用打包为 Docker 镜像，先在自己电脑上运行，再推送到阿里云容器镜像服务（ACR），最后让弹性容器实例（ECI）运行它，并从浏览器访问公网 HTTP 地址。ECI 负责运行容器，你将不需要在服务器上手动配置 Python、Nginx 或 SSH。

## 如何开始

先准备个人 Fork 的 `isse-labs/` 仓库、已完成的 Lab 2 项目、可用的 Docker、阿里云账号和**专为实验创建**的 DeepSeek Key。若 Docker 或云账号尚未准备好，可在 Codex 引导下逐项检查。

在 Codex Desktop App 中以个人 Fork 的 `isse-labs/` 仓库根目录打开新任务，发送：

```text
请完整阅读 lab3/AGENTS.md 和 lab3/README.md，从准备个人工作目录开始，按顺序引导我完成 Lab 3。
```

建议全程使用同一个 Codex 对话。课程 `lab3/README.md` 和 `lab3/AGENTS.md` 只读；下文是给 Agent 使用的交互式流程。

### 安全提醒

- **保留 Lab 2 的 Key 方式**：`DEEPSEEK_API_KEY` 由 Flask 后端从环境变量读取。前端不输入、不接收也不保存 Key；不要把真实 Key 写进 Docker 镜像、源码或 Git。
- 使用专门创建、可随时废除的实验 Key，不用长期或重要项目的 Key。结束测试后建议**废除该 Key**，并**释放本实验创建且不再使用的计费云资源**。

> 如果你是人类，则不必再继续阅读本 README 文件，后续任务只需在 Codex 中交互完成。 请不要修改本文件与同路径下的 AGENTS.md 文件。

## 作业目标与提交内容

完成后，学生应能说明 Docker 镜像、ACR、ECI、公网 IP、Flask、前端与 DeepSeek 各做什么；能亲自验证本机容器和公网应用，并理解为什么释放 ECI 后网页不能再访问。

在个人 Fork 的最新主分支上创建 `lab3/<学号>-<姓名>` 分支，在仓库内创建同名目录 `lab3/<学号>-<姓名>/`。只提交该目录中的个人作业文件，最后 Push 并发起标题为 `<学号>-<姓名>` 的 PR。个人目录至少包含：

```text
lab3/<学号>-<姓名>/
├── app.py
├── frontend/                 # 沿用 Lab 2 前端
├── requirements.txt
├── Dockerfile
├── .dockerignore
├── .gitignore                # 必须排除 .env 和个人凭据
├── .env.example              # 只有变量名和示例值
├── README.md                 # 项目、镜像、部署和验证说明
└── AGENT_TRACE.md            # 最后由学生复制真实对话或填写分享链接
```

若原项目有其他必要的非敏感文件，按实际结构保留。**不得提交** `.env`、真实 Key、ACR 登录密码、阿里云凭据、虚拟环境、缓存、真实聊天数据。不要为了匹配目录示意而加入无用文件。
