# Lab 3：从代码到云端——ACR 构建与 ECI 部署

本 Lab 延续 Lab 2 的 HTML/CSS/JavaScript + Flask + DeepSeek 聊天应用。你将与 Coding Agent 协作编写 `Dockerfile`，把代码提交到个人 GitHub Fork 仓库；然后使用阿里云容器镜像服务（ACR）根据代码**在云端构建镜像**，弹性容器实例（ECI）拉取并运行镜像。最后，你从自己的浏览器访问云端应用。

### 实验边界与安全

- **沿用 Lab 2 的后端 Key 方式**：Flask 在运行时从 `DEEPSEEK_API_KEY` 环境变量读取 Key。前端不输入、不接收、不保存 Key；真实 Key 不得进入 GitHub、Dockerfile、构建上下文、镜像、ACR 构建参数、日志或 Codex 对话。
- 本 Lab 为短时教学演示，公网入口使用 **HTTP**。浏览器发出的聊天内容未加密，不要输入敏感信息。公开的聊天 API **没有鉴权**，别人仍可能借后端 Key 调用模型。这不是正式服务的安全部署方案。
- 测试后建议**废除实验 Key**，并务必**释放本实验创建且不再使用的 ECI 等计费资源**。

### 开场讲解：由 Agent 在首次回复中讲给学生

> [AGENT ACTION]

学生可能完全没有全栈开发与云计算经验。**在给分支命令、要求学生操作之前**，用连贯的生活化例子解释下面所有概念及彼此关系；不能只罗列名词或让学生自己阅读本段，也不要一次性跳到创建 ECI。可分几个短段落，但首次回复应完成这次开场讲解，然后自然过渡到第一项学生操作。

| 必须解释的概念 | 讲解时要说清楚的要点 |
| --- | --- |
| 云计算 | 按需租用云厂商的计算、网络等资源，应用不再只能在自己的电脑上运行；云资源有费用。 |
| Docker |
| Dockerfile | 构建说明书：以哪个基础环境开始、复制什么文件、安装哪些依赖、运行什么命令。它不是镜像；后续会逐行讲解并让学生思考配置。 |

| ECI / Serverless | ECI 直接运行镜像，免去自己管理 ECS；“Serverless”指少管理服务器，**不是运行中免费**。实例即使无人访问仍按时长产生费用，DeepSeek 调用又可能另行计费。 |

最后把它们连成一条具体路线：`Lab 2 代码 + Dockerfile → Push 到个人 GitHub Fork → ACR 云端构建并保存镜像 → ECI 运行镜像 → 公网 IP → 浏览器访问`。说明 Flask/Gunicorn 在容器里提供前端页面与 API，DeepSeek 实验 Key 只在 ECI **运行时**由学生设置为环境变量；当前公网 API 无鉴权，演示后要删 ECI。明确 Agent 负责代码、讲解和排错，学生亲自执行命令、操作云控制台、核对价格并验证页面。讲完再开始准备分支。

## 任务 1：整理应用并编写 Dockerfile

> [AGENT ACTION]

先向学生逐行解释 Dockerfile 的常见构成，再根据**实际项目**编写，不机械套固定模板：

| 常见指令 | 在本项目里的作用 | 配置时要核对什么 |
| --- | --- | --- |
| `FROM` | 选择含 Python 的基础镜像。 | Python 版本与项目依赖兼容；基础镜像不能自带实验 Key。 |
| `WORKDIR` | 设置容器里的工作目录。 | 后续相对路径、Flask 静态文件路径应一致。 |
| `COPY requirements.txt ...` | 先复制依赖清单。 | 构建上下文是**个人目录**，不是仓库根目录。 |
| `RUN pip install ...` | 在镜像构建阶段安装依赖。 | 包含 `gunicorn`；失败要看 ACR 构建日志。 |
| `COPY ...` | 复制应用和前端。 | `.dockerignore` 排除 `.env`、缓存、真实聊天数据、轨迹。 |
| `EXPOSE 5001` | 说明容器预期提供的端口。 | 它是元数据，不会自动创建公网入口；ECI 还要配置端口与网络。 |
| `CMD` | 镜像运行时启动 Gunicorn。 | 单 worker，监听 `0.0.0.0:5001`，入口与实际 Flask 对象匹配；不要用 debug 服务器。 |

完成最小改造：保留原前端、Flask API 和 CRUD；同一容器提供页面、静态资源、API，前端 `fetch()` 用同源相对路径；后端只在运行时读取 `DEEPSEEK_API_KEY`。增加 Gunicorn 依赖；创建 Dockerfile、`.dockerignore`、`.gitignore`、无真实值的 `.env.example`。不得把 Key 放进 Dockerfile 的 `ARG`/`ENV`、源码或构建参数。若程序把聊天数据写入本地 JSON，说明 ECI 容器文件是临时的，本 Lab 不要求持久化。

不要求本地安装或运行 Docker。Agent 先做静态检查和可行的本地非敏感测试；学生亲自查看文件、在适合自己系统的终端里检查 `.env` 未被 Git 跟踪。Agent 读取本次 Git 状态核验，但不打开 `.env`。完成后创建有意义的代码 Commit；学生亲自 Push 到**个人 Fork**，Agent 核验远端分支可见。ACR 只能构建已 Push 的版本。

## 任务 3：创建 ECI、取得公网地址

> [AGENT ACTION]

先解释：ECI 会把 ACR 镜像作为运行中的容器；它不是 ECS 云服务器。创建页可能调整，以实际字段为准。引导学生**逐项**填写，先看价格再确认创建：

| 控制台项目 | 本 Lab 建议选择 | 为什么 |
| --- | --- | --- |
| 地域 | **华北 2（北京）**，与 ACR 同地域。 | 便于选择本人镜像，避免跨地域问题。 |
| 计费方式 / 实例数 | 按量付费，**1 个**实例。 | 只做短时实验；运行期间持续计费。 |
| 实例名称 | ASCII 名称，如 `lab3-<学号>`。 | 便于识别和最后删除。 |
| 算力类型 / 规格 | **经济型**，选择控制台允许的最低规格；若显示 `0.25 vCPU / 0.5 GiB`，优先从它开始。 | 降低短时费用；若内存不足，再诊断并征得学生确认后调整。 |
| 镜像 | “我的镜像”中选本人 ACR 的**确切仓库与标签**。 | 避免运行旧版或公开的同名镜像。 |
| 容器端口 / 协议 | `5001 / TCP`。 | 与 Gunicorn 监听端口一致。 |
| 启动命令 / 参数 | 默认沿用 Dockerfile 的 `CMD`；不重复覆盖。 | 避免因控制台命令写错导致容器无法启动。 |
| VPC / 交换机 | 用控制台推荐的同地域现有网络；没有时按向导创建最小可用网络。 | ECI 需要网络；不为本实验额外购买复杂网络产品。 |
| 安全组 | 先使用页面**默认选择/默认配置**，不用专门创建或逐条修改。 | 若公网不通，再由 Agent 检查实际端口规则并排错。 |

| 容器高级设置 → 资源/健康检查/日志 | 资源限制不超过实例规格；其他先保留默认，除非应用实际需要。 | 避免额外配置造成启动失败。 |
