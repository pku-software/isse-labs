```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt ./
```

逐行来看：

1. **`FROM python:3.12-slim`**  
   从带有 Python 3.12 的精简基础镜像开始，无需自己安装 Python。它不包含你的实验 Key。

2. **`WORKDIR /app`**  
   设置镜像里的工作目录为 `/app`，后面的复制、安装和启动都以这里为工作位置。这是容器内的路径。

3. **`COPY requirements.txt ./`**  
   先把依赖清单复制到 `/app`。这里的来源是你的个人目录，所以后续 ACR 的构建上下文必须指向 `lab3/2300017804-ChenChuanze/`。

4. **`RUN pip install --no-cache-dir -r requirements.txt`**  
   在**构建阶段**安装 Flask、OpenAI SDK、python-dotenv 和新增的 Gunicorn。`--no-cache-dir` 不保留 pip 下载缓存，减少镜像中的多余文件。

5. **`COPY . .`**  
   把个人目录中未被 `.dockerignore` 排除的文件复制到 `/app`。因此镜像能同时提供应用代码和 `frontend/` 页面资源。

6. **`EXPOSE 5001`**  
   声明应用预期使用的端口。它是说明性元数据，不会自动创建公网入口或放行网络规则。

7. **`CMD [...]`**  
   这是**运行阶段**执行的启动命令。`app:app` 指 `app.py` 中的 Flask 对象 `app`；`0.0.0.0:5001` 表示监听容器各网络接口的 5001 端口。后续 ECI 访问配置要与实际监听端口对应。导入 `app.py` 不会执行其 `__main__` 中的 debug 启动代码。以上指令的职责可参照 [Docker 官方说明](https://docs.docker.com/build/concepts/dockerfile/)。

这里使用 **单 worker**，因为你的会话状态保存在进程内；多个 worker 会各自持有不同的状态。`--timeout 180` 给模型请求留出等待时间，超过该限制而无响应的 worker 仍会被终止并重启。[Gunicorn 超时说明](https://gunicorn.org/reference/settings/#timeout)

`.dockerignore` 排除了 `.env*`、虚拟环境、缓存、聊天数据、截图、对话轨迹、README 和测试文件。因此真实 Key 不会被复制进镜像；它由你在 ECI **运行时环境变量**中设置，后端继续读取它。

构建按顺序执行。某一步失败或中断，后面的步骤不会继续；修复后要重新触发构建。未变化的前面步骤可能复用缓存，但 **ACR 不保证断点续跑**，也不能认为它一定从失败的位置继续。
