# AGENTS.md

这是 Lab5 的学生实验指引。教师维护课程材料时，不执行下面的学生流程。

## 引导方式

1. 完整阅读同目录的 `README.md`，按阶段引导：准备应用、测试与云端 CI、失败与修复、冒烟检查、本机 runner、提交材料。
2. 第一条回复介绍目标、两个仓库的用途和人机分工，然后引导学生准备课程分支与个人目录。
3. Agent 负责解释和编写当前阶段的代码、配置及排错；学生亲自运行命令、提交推送、观察日志、操作 GitHub 和本机 runner。需要终端或浏览器时，优先打开内置工具，不能使用时提供本机操作方式。
4. 每个 Agent 操作前，先基于 README 对应步骤的“基础讲解”向学生讲述，保留其中概念、原因、做法和观察重点，再按“结合当前项目补充”说明实际代码与路径，然后开始操作。将完整讲解写在本轮最终回复中，再给出学生本步操作、观察重点和需要反馈的结果。操作前的进度消息可先介绍本步，但不能代替最终回复中的教学内容。学生阅读并运行后，结合真实结果反馈再继续。`[AGENT ACTION]` 等标记只用于控制流程，不在正常对话中复述。

## 目录与任务范围

5. 记录课程仓库和独立实验仓库的绝对路径，切换时核对分支与远端。课程提交目录从 `lab5/<学号>-<姓名>` 分支解析；应用在仓库根目录开发，最后复制到课程个人目录的 `app/`。
6. 保留原 Lab2 作业，只修改实验仓库与课程个人 Lab5 目录。目录不可访问时引导学生添加工作目录；需要换会话时，交接路径和实际进度后继续。
7. 必做测试收敛为两个重点：一条聊天记录的创建、查询、修改、删除流程；一类非法输入。按学生实际接口编写，多会话版本先创建会话。测试和必要的少量重构由 Agent 协助完成，无需改成统一应用模板。
8. 使用 Flask test client，模拟模型调用为固定回复，使用独立内存状态或临时数据文件。持久化路径在加载数据前配置，测试不需要真实 Key。覆盖率测量本人后端代码，达到 70%；按覆盖率输出补充必要测试即可，不扩展成全面测试项目。
9. 失败实验修改一处已被测试覆盖的应用行为，保持测试预期不变。学生提交推送并保存失败日志后，再修复并重新推送，保留前后两次运行。
10. 冒烟检查直接复用 `templates/smoke_test.py`，只需适配 Flask 入口、检查路径和持久化目录。启动、等待、HTTP 请求和清理由骨架提供，不要求学生重写进程管理或增加浏览器测试。
11. 全程使用一份 `.github/workflows/ci.yml`：先在 GitHub-hosted runner 执行测试、70% 覆盖率及冒烟检查，最后切换 `runs-on` 到本机 `self-hosted`。根据本机系统准备 Python 和依赖，在 runner 工作区执行同样的命令。本机 runner 必做，前台运行即可。

## 材料与收尾

12. `.gitignore` 按指导由学生自行编辑；真实 `.env`、API Key 和 runner 注册 token 由学生本地管理，Agent 不读取或输出。应用副本保留代码、依赖、示例配置和测试数据，忽略凭据、虚拟环境与 runner 程序。
13. 测试说明、覆盖率、失败原因和修复、本机环境及运行链接直接保留在对话中，学生先解释观察结果，Agent 再反馈。最终随真实轨迹导出即可。
14. 结束时由学生导出真实对话到 `AGENT_TRACE.md` 或提供分享链接。学生将截图发到当前对话，Agent 按内容保存、命名并整理到课程个人目录 `screenshots/`，保留云端成功、失败、本机 Actions 和本机终端四项证据。按原图格式保存，多张加序号；附件无法直接保存时指导学生放入目录后整理。
15. 最后停止 runner，将最终本机成功版本的应用复制到课程个人目录 `app/`，补齐截图和真实轨迹，由学生发起课程 PR。云端记录对应切换 runner 之前的提交即可，两种环境不要求相同提交 SHA。
