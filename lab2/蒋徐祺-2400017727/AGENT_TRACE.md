**前端是怎么调用后端的**

`frontend/app.js` 里所有数据操作都是通过 `fetch()` 发出 HTTP 请求完成的：

- 页面打开时 → `GET /api/messages` 拉取全部记录并渲染；

**Key 是怎么被读取的**

程序启动时会执行 `load_dotenv(... .env)`，它把 `.env` 里的内容读进当前进程的环境变量；真正需要 Key 的时候，代码用 `os.getenv("DEEPSEEK_API_KEY")` 把它取出来，拼进请求头 `Authorization: Bearer <你的Key>` 里发给 DeepSeek。整个过程中：Key 没有写在源代码里；它只存在于 Flask 进程的内存和通往 DeepSeek 的那次 HTTPS 请求里；浏览器、页面源码、我们的对话里都不会出现它。

**一次问答现在走的路径**

浏览器里的页面 →（`fetch` 发 `POST /api/messages`）→ 你的 Flask →（`requests.post` 带着 Key 请求 DeepSeek）→ DeepSeek 返回模型文本 → Flask 把文本作为 `reply`，和用户消息一起存进内存里的记录 → 返回 JSON 给浏览器 → 页面显示出来。注意方向是单向的：浏览器只跟 Flask 说话，永远不直接碰 DeepSeek。

**出错时的处理**

四种情况都会返回带 `error` 字段的 JSON 和 502 状态码，Flask 不会崩：没读到 Key、连不上 DeepSeek、DeepSeek 返回非 200（比如 Key 无效或余额不足）、返回数据结构不符合预期。对外的接口约定完全没变，所以前端一行都不用改。
