# Lab 1：Git 版本控制与协作

## 实验目标

通过本实验熟悉 Git 的基本版本控制操作，并体验基于 GitHub 的分支开发、Pull Request（PR）、代码合并和冲突解决流程。

## 任务 1：个人版本管理

1. Fork 本课程仓库 [`pku-software/isse-labs`](https://github.com/pku-software/isse-labs)，然后将自己的 fork 克隆到本地。
2. 在 `lab1/` 下创建自己的提交目录，命名为 `<姓名>-<学号>`。
3. 在个人提交目录中创建 `diary.txt`，写下今天上课的感受，然后完成第一次提交，并设置一句提交信息。
4. 修改 `diary.txt`，追加一句话，然后完成第二次提交。
5. 使用 `git log --oneline` 检查提交历史。


## 任务 2：远程仓库操作

1. 将本地 `main` 分支推送到自己的课程仓库 fork。
2. 在 GitHub 网页中确认个人目录、文件和两次提交记录已经成功同步。


## 任务 3：小组协作开发

1. 每组选择一名组长，组长在自己的 GitHub 账号下创建一个公开仓库，并邀请其他组员成为该仓库的 Collaborator。
2. 每位组员从 `main` 创建自己的分支，建议命名为 `student-<学号>`。
3. 每位组员在自己的分支中创建 `<学号>.txt`，写下自己对小组沟通与协作的预期。
4. 每位组员将分支推送到小组仓库，并向 `main` 发起 PR。
5. 组长检查并依次合并所有组员的 PR，最终在 `main` 中形成完整的小组成果。

## 任务 4：冲突解决体验

1. 组长在  `main` 分支根目录创建 `group-note.txt`，内容为：

   ```text
   这是小组共享笔记
   ```

2. 所有组员先同步这次修改，并分别从同一个最新 `main` 创建 `conflict-<学号>` 分支。此时先不要合并任何人的冲突练习 PR。
3. 每位组员都在自己的冲突练习分支中修改 `group-note.txt` 的第一行，加入自己的签名，例如：

   ```text
   我是学号20260101
   ```

4. 每位组员通过 PR 提交修改。第一个合并的 PR 通常不会发生冲突；从第二个 PR 开始，由于大家修改了同一行，应当出现合并冲突。
5. 遇到冲突的同学需要同步小组仓库的最新 `main`，在本地或 GitHub 网页中保留已有签名并加入自己的签名，解决冲突后再次推送。
6. 最终的 `group-note.txt` 应包含全体组员的签名，例如：

   ```text
   我是学号20260101
   我是学号20260102
   我是学号20260103
   我是学号20260104
   这是小组共享笔记
   ```

## 最终提交内容

### 提交目录

每位同学在自己的课程仓库 fork 中，将所有提交内容放在以下目录：

```text
lab1/<姓名>-<学号>/
├── diary.txt
├── README.md
└── images/
    ├── group-pr.png
    ├── conflict.png
    └── group-result.png
```

各文件的要求如下：

- `diary.txt`：任务 1 中创建并通过至少两次提交完成的文件。
- `README.md`：填写个人信息、小组仓库地址。
- `images/group-pr.png`：本人在小组仓库中发起 PR 的截图。
- `images/conflict.png`：任务 4 中出现并解决合并冲突的截图。第一位合并、未遇到冲突的同学可以提交相应 PR 已成功合并的截图，并在 `README.md` 中注明未遇到冲突。
- `images/group-result.png`：小组仓库最终 `main` 分支的成果截图，应能看到组员文件和合并完成的 `group-note.txt`。


### 发起课程仓库 PR

1. 确认任务 1～4 均已完成，并将上述文件提交到个人 fork 的 `main` 分支。
2. 将个人 fork 的 `main` 推送到 GitHub。
3. 从个人 fork 的 `main` 向课程仓库 `pku-software/isse-labs` 的 `main` 发起 PR。
4. PR 标题使用以下格式：

   ```text
   [Lab1] 姓名-学号
   ```
